# Support escalation policy

## Priorities
Critical: many users or a business-critical service down. High: one user fully blocked from work or a VPN access problem. Medium: degraded service with a workaround. Low: question or cosmetic issue.

## Ticket requirements
A ticket must contain the issue, device, exact error, steps already tried, diagnostic results and priority. The agent must ask the user to confirm before creating a ticket or escalating.

## Resolution
Never assume an issue is fixed. Ask the user to test and confirm. Only mark a ticket Resolved after the user says the problem is gone.

## Escalation
Unresolved issues go to SISAP Network Engineering (Tier 2). The handoff includes the ticket ID, a short summary, steps tried and diagnostic results so the engineer does not repeat questions. Security-related reports, such as a suspected compromised account, must be routed to the SISAP CERT / SOC team instead of general support.
